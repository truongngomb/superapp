=== WORKFLOW — GIT STAGED COMMIT MESSAGE & COMMIT ===

1. Kiểm tra staged changes bằng lệnh:
// turbo
```powershell
git diff --cached --name-only
```

2. Nếu không có file nào trong stage, thông báo cho người dùng và DỪNG workflow.

3. Lấy nội dung chi tiết staged diff:
// turbo
```powershell
git diff --cached
```

4. Phân tích nội dung diff và tạo Git commit message theo đúng các nguyên tắc sau:

   **NGUYÊN TẮC CỐT LÕI:**
   - Ngôn ngữ: **TIẾNG VIỆT**
   - Định dạng: `type(scope): Mô tả ngắn`
   - Type: `feat, fix, refactor, perf, docs, test, chore, ci, build`
   - Scope: Module/Feature bị ảnh hưởng (viết thường, không dấu)
   - Tiêu đề: ≤ 72 ký tự, động từ mệnh lệnh (Thêm, Khắc phục, Tối ưu...), không dấu chấm cuối dòng.
   - Nội dung: Tập trung vào "Cái gì" và "Tại sao".

5. Thực hiện commit với message vừa tạo:
// turbo
```powershell
git commit -m "<nội dung commit message đã tạo>"
```

6. Báo cáo kết quả cho người dùng.

=== QUY TẮC CỤ THỂ CHO AI ===

Bạn là một Senior Software Engineer. Khi thực hiện bước 4, hãy đảm bảo commit message cực kỳ chính xác dựa trên logic code thay đổi.

**QUY TẮC PHÂN TÍCH STAGED DIFF:**
- Chỉ dựa trên nội dung xuất hiện trong `git diff --cached`
- Tuyệt đối không bao gồm các file chưa stage.
- Đổi format / comment / rename thuần túy → chore hoặc refactor.
- Nếu thay đổi ảnh hưởng logic chạy → KHÔNG dùng chore.

**YÊU CẦU ĐẦU RA (Bước 4):**
- Tạo ra nội dung commit message hoàn chỉnh để dùng cho lệnh commit ở bước 5.
